# Лабораторная работа №11. JSON и HTTP

**Вариант 1 — все задачи выбранного пользователя.** Используются стандартные библиотеки Python, дополнительные пакеты не нужны.

## Файлы
- `todos.json` — исходные учебные задачи.
- `analysis.py` — проверка данных, подсчёт выполненных задач, поиск лидеров и выборка пользователя.
- `main.py` — чтение JSON, вывод результатов и запись файлов.
- `leaders.json` — завершённые задачи пользователей-лидеров.
- `selected.json` — все задачи выбранного пользователя (пример для `user_id=5`).
- `fetch_profile.py` — запрос профиля GitHub или чтение локального примера.
- `profile_sample.json` — учебный локальный профиль для работы без сети.
- `test_analysis.py` — автоматические тесты.

## Запуск
В терминале перейдите в папку с файлами и выполните:
```bash
python3 main.py
```
При запросе `user_id` введите `5`. Пример вывода:
```text
Количество выполненных задач: {5: 2, 10: 2}
Лидеры: [5, 10]
ID завершённых задач лидеров: [1, 3, 4, 5]
Введите положительный user_id: 5
Задачи пользователя 5: [1, 2, 5]
Результаты записаны в leaders.json и selected.json
```
Если ввести неверный ID (например, `0` или буквы), ввод повторится. Если пользователь отсутствует, выборка пустая.

## HTTP-задание
```bash
python3 fetch_profile.py
```
- Пункт **1**: введите логин `octocat` для одного сетевого запроса. Профиль сохраняется в `profile.json`.
- Пункт **2**: используется `profile_sample.json`, программа читает его с помощью `json.load` и выводит `demo`. **Это учебные локальные данные, а не реальный ответ GitHub.**
`https://api.github.com/users/<login>` — адрес API для получения профиля пользователя GitHub. `GET` — HTTP-метод чтения; `urlopen()` с `Request` отправляет запрос GET. `timeout=10` ограничивает ожидание ответа десятью секундами. `HTTPError` обрабатывает ответы сервера с ошибкой (например, 404), `URLError` и `TimeoutError` — проблемы соединения, `ValueError` — неправильные данные, `UnicodeError` — ошибки кодировки, `OSError` — проблемы с файлами. Сетевой запрос не запускается при импорте модуля.

## Проверка
```bash
python3 -m unittest -v test_analysis.py
```
Тесты проверяют исходный набор, пустые данные, отсутствие завершённых задач, одного и нескольких лидеров, выборку варианта 1, ошибки структуры и сохранение JSON без изменения данных.

## Основные функции
- `validate_todos(data)` — проверяет список, поля, их типы и уникальность `id`.
- `completion_counts(todos)` — считает завершённые задачи для каждого пользователя, в том числе с нулём.
- `top_users(counts)` — выдаёт список лидеров по возрастанию ID либо `[]`.
- `leader_tasks(todos, leaders)` — берёт завершённые задачи лидеров, сохраняя порядок.
- `select_tasks(todos, user_id, parameter=None)` — в варианте 1 выбирает все задачи пользователя; параметр не нужен.

В `main.py` входные данные сначала читаются и полностью проверяются, а лишь затем записываются результаты. Поэтому при ошибке входного файла старые результаты не перезаписываются.
